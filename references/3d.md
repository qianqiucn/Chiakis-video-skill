# 3D & 2.5D Depth: Dual-3D Flagship (Three.js Stylized Graphic-3D + Blender Cinematic 3D)

Read before storyboarding or building any shot that needs optical parallax, true 3D typography, camera travel through space, or 3D elements. Pixel measurements assume the 1920×1080 timeline (`snap.mjs --scale 1`; scale by ⅔ on 720p) at 24 fps.

> **Dual-3D Flagship Requirement (Client-Selectable)**: Both **Three.js Stylized Graphic-3D (`lib/three_kit.js` + `fonts.py glyph3d`)** and **Blender Cinematic 3D (`depth_relief.py`, `projection/`, built sets)** are first-class flagship quality standards — they are **parallel artistic media, not a downgrade fallback**. The client freely chooses their 3D engine mix in `docs/PROMPT_TEMPLATE.md` (`全能双 3D 旗舰` / `Three.js 风格化 3D` / `Blender 电影级 3D` / `纯 2D`):
> - **Three.js (`§5e`)** owns **2D-native Stylized Graphic-3D**: extruded CJK/JP/Latin 3D typography, 360° character-orbiting lyric ribbons (`drawBack` / `drawFront` Z-sandwich), 3D kinetic typography corridors, stylized graphic-3D architectural spaces/grids, real-time chromatic glass prism refractions over live 2D canvases, `z = 60` 3D louver transitions, and zero-Blender WebGL 2.5D micro-reliefs — crisp `NoToneMapping` / `SRGBColorSpace` graphic ink & cel looks that blend natively into 2D illustration & lyric PVs (including on machines with Blender installed!).
> - **Blender (`§3.2`, `§3.6`, `§5b–§5d`)** owns **Cinematic & Photoreal / Painterly 3D**: Cycles/Eevee physical lighting, optical aperture DOF, camera projection into painted artwork, built PBR/Kuwahara sets (`AL.anime_look`), and complex multi-object optical mechanisms.

## 1. The target: shots about space must prove their depth
- Object inserts take a gentle push/pull and character portraits ride their own 2D motion (`style-grammar.md` §6c, §2 below). Only a shot **about space** (a hall, alley, room, stage, skyline) must read as genuine 3D: the nearest foreground subject and the far background visibly slide past each other.
- **PASS target**: **≥ 20 px** subject-vs-background separation and **≥ 15 %** of overall frame motion over ~23 frames (`scripts/vision/parallax.py` defaults; aim for 25–30 px). Scale `--target-px` proportionally for shorter shots (≈ 1 px/frame), keeping the ≥ 15 % share.
- **Exempt**: macro object inserts on a gentle push/pull, portrait shots driven by character 2D motion, 2–6-frame strobe bursts, and flat action composites (`house-style.md` §4).
- **How to measure**:
  ```bash
  python -X utf8 <sk>/scripts/vision/depth.py first.png first_depth.png --bits 16
  python -X utf8 <sk>/scripts/vision/parallax.py first.png last.png --depth first_depth.png --out work/parallax_check.jpg
  ```
  - Exit `0 = PASS`. On timeline captures (`snap.mjs --scale 1 --png`), pass `--exclude 0,0,200,60` to ignore the frame label, plus boxes for HUD/titles or flashing lights (lights turning on can fool optical flow into a fake PASS).
  - For character shots, pass the character alpha mask as `--depth` so separation is measured cleanly between the subject and background.

## 2. Method by shot type
| Shot type | First choice | Key numbers |
|---|---|---|
| Character close-up / portrait | 2D layered motion (`T3.her.wave`, `T3.her.eyes`, §8) with near-still camera; or separated cutout over clean plate on `lib/multiplane.js` (§3.1) | Camera ≈ 2–6 px/f; multiplane yields 20–40 px clean occlusion from small moves |
| **Space to travel into or open up** (hall, library, street, city, room; push-in or pull-back) | **Real 3D**: **camera projection** (§3.6) for ornate illustration-specific spaces, or a **built Blender set** (§5b–§5c) for modular/look-around spaces | Near layer vs far wall ≥ 20 px (projection easily reaches 60–100 px); check disoccluded edges on projection; render a look-dev still first on built sets |
| Subject inside a deep space | Family chosen per row above (§5c; in a built set, place the 2D illustration as a grounded unlit card via `AL.emissive_card` + `AL.contact_shadow`), or §3.1 for gentle drifts | Architecture, pillars, and shelves give real occlusion edges for free |
| Landscape, sky, distant skyline | **Blender 2.5D depth relief** (`scripts/blender/depth_relief.py`, §3.2) with `--orbit` or `--crane` + near foreground cue + particles at depth | `--orbit ±6°–9°` (ceiling ±11°; `--overscan 1.15` holds edges to ±16°) or `--crane ±8°–10°` |
| Object insert & macro scene (book, emblem, mic, droplet, keycap) | Gentle push/pull on one-picture relief (`--push 0.25–0.35 --truck 0.08 --dof 0.25`) with real aperture DOF + drifting dust | Peak ≈ 4 px/f; macro scenes stay on relief — shallow depth + strong DOF sells scale for a fraction of a full build |
| **Typographic 3D / Lyric PV hero** (3D extruded CJK/JP/Latin title, character-orbiting lyric ribbon, 3D lyric corridor) | **Three.js Graphic-3D** (`T3.three.extrudeText` + `fonts.py glyph3d`, `T3.three.textRing`, `T3.three.textCorridor`, §5e); or `lib/emblem3d.js` for flat CSS emblems | Zero Blender render wait; flat/toon+ink/glass/wire shaders match 2D illustration directly; `textRing` Z-sandwiches cleanly around RGBA cutouts |
| **Stylized graphic 3D space / 3D transition / live refraction** (geometric grid, monolith horizon, 3D blinds wipe, chromatic glass bars over 2D) | **Three.js Graphic-3D** (`T3.three.field`, `T3.three.louverTransition`, `T3.three.prismOverlay`, `T3.three.stage`, §5e) | Deterministic per-frame WebGL composited straight onto 2D `<canvas>` via shared singleton renderer (`NoToneMapping`, `SRGBColorSpace`) |
| Brief 1–2 beat subtle insert or zero-Blender relief | **Three.js** `T3.three.relief` (§5e) or WebGL2 `lib/depth3d.js` (`cam.depth3d`) | Keep `relief` orbit ≤ ±9° / `depth3d` `x/y <= 0.04` so occlusion edges never tear |
| Action shot | Flat 2D composite or multiplane matching contact surfaces; or 3D card/model seated at contact depth inside a built set | Never place a flat mover over an orbiting 2.5D relief |

## 3. Recipes

### 3.1 Subject on its own plane (real occlusion)
When you have a clean background plate and a separated foreground RGBA cutout:
- **Browser `lib/multiplane.js`**: `{ src: plate, z: 1200–2000 }`, `{ src: subject, z: 0 }`, optional `{ src: fg, z: -300, blur: 6 }`. With perspective `P = 1200`, trucking 40–60 px yields 20–35 px of clean occlusion; `rotY ±1–1.5°` yields 20–40 px.
- **Blender two-plane scene**: displace the clean plate with `depth_relief.py` logic and float the RGBA subject plane `dz = 0.6–0.9` in front, scaled `(D - dz) / D` (`D = 2.78`) to preserve framing.

### 3.2 Blender 2.5D depth relief (`depth.py --soften` → `depth_relief.py`)
1. Generate a softened 16-bit pixel-aligned depth map (`--soften` runs median-7 + Gaussian-5 so silhouettes do not tear like rubber):
   ```bash
   python -X utf8 <sk>/scripts/vision/depth.py art.png work/art_depth_soft.png --bits 16 --model small --soften
   ```
2. Render headless through `scripts/run_queue.py blender`:
   ```bash
   python -X utf8 <sk>/scripts/run_queue.py blender --lane relief -- \
     blender -b --python <sk>/scripts/blender/depth_relief.py -- \
     --image art.png --depth work/art_depth_soft.png --out web/assets/rel/shot01 \
     --frames 48 --fps 24 --orbit -8 --crane 4 --target-uv 0.5,0.45 --push 0.08 --strength 0.30 --dof 0.28 --subdiv 8
   ```
- **`--target-uv` & `--target-depth auto`**: places the pivot Empty on the near subject so the subject holds steady while the background slides.
- **Sign convention**: `--orbit +` moves the camera left-to-right (background behind pivot slides right); `--crane +` lifts the camera (background slides up). Combine both for diagonals.
- **Displacement cap**: keep `--strength 0.22–0.35`. If a shot still reads flat, add a blurred foreground element (§3.3) or separate layers (§3.1) rather than cranking `--strength` past `0.4`.
- **Colour fidelity**: `depth_relief.py` forces `view_transform = "Standard"` so illustration colours match verbatim with zero AgX/Filmic tone shift. Eevee renders ~0.3 s/frame at 1080p; `--engine cycles` auto-selects `OPTIX`, `CUDA`, `METAL`, `HIP`, or `ONEAPI`.

### 3.3 Foreground depth cues
Give the camera something to slide against: textured or lit backgrounds (never blank black behind a subject), a softly blurred foreground prop passing the lens on ~1 in 3 shots, depth-projected particles (§7), and subtle atmospheric haze toward the background colour.

### 3.4 Overlays ride the same camera
Keep foreground dust, bokeh, and accents moving in the **same direction** as the 3D camera (faster when nearer). Never stack a large CSS 2D zoom/pan on top of a Blender 3D sequence — it inflates global motion without adding parallax, dropping the parallax ratio.

### 3.5 Real optical DOF
On `depth_relief.py`'s 2-unit scene scale, visible optical blur begins around **`--dof 0.20–0.35`** (`f/2.8` is nearly sharp everywhere). For room-scale 3D texture layers (props 7–10 m away), bring foreground props close to the lens or drop the f-stop (`f/0.12–0.25`) so depth blur reads cleanly at 720p/1080p.

### 3.6 Camera projection into an intricate painted space (`scripts/blender/projection/`)
Use when pushing into or pulling back from an ornate illustration (book stacks, cathedral tracery, hand-painted streets) whose bespoke detail would take hours to model from scratch:
- Copy `scripts/blender/projection/` into `<project>/blender/<SHOT>/eng/scripts/` and follow its `README.md`.
- Recover focal length `F` and pitch `TH` from the illustration's converging verticals and horizon; sit vertical alpha cards (`vplane()`) on a shared floor plane over the depth-displaced clean plate (`design.py sim` → `design.py build <y0>`).
- Upscale card textures 2× Lanczos (`textures.py`) so pushing 1.15–1.6× stays sharp, and render beauty + mask passes (`dolly_scene.py`, queued via `run_queue.py blender`).
- Frame 1 matches the original painting pixel-for-pixel; the camera then dollies smoothly on a quartic ease-out (`travel(n)`).
- Push only as deep as the plate holds (typically ≤ 1.4× magnification); fill revealed gaps by continuing the illustration's own texture, never by mirroring (which creates kaleidoscope artefacts).

### 3.7 Practical screen shoot
When a shot features a close-up UI or terminal display in physical space, render a real screen mesh in Blender with a subtle subpixel texture, specular glass layer, and 6-blade aperture DOF, aimed per beat via camera lens shift. Let the graphic designer lock the typography in `board.md` so the 3D screen matches the 2D film's type system, and verify 2–3 full-res stills at phone readability before batch rendering.

## 4. Don't
- **No straight push on a dead-centre subject** (parallax is zero at screen centre).
- **No opposing truck that cancels push parallax** (when pushing in, truck slightly *away* from an off-centre subject so it separates against the background).
- **No cranking `--strength` alone on a softened relief** (produces rubbery halos without true occlusion).
- **No `opacity`, `filter`, or `mask` on a CSS `preserve-3d` parent** (flattens 3D children; fade inner planes or outer wrapper instead).
- **No AI-painted depth maps** (misaligned edges cause ghost halos; always use `scripts/vision/depth.py`).
- **No blurry CSS upscaling on close-ups**: supply source assets at ≥ final on-screen pixels (or lay out type at 2× on a ½-scaled plane) instead of magnifying blurry bitmaps.

## 5b. Free 3D asset library (`scripts/assets3d.py` & `scripts/blender/asset_lib.py`)
Borrow before building generic geometry from scratch. `scripts/assets3d.py` (Python stdlib only) searches and caches four open libraries into `CHIAKI_ASSETS3D` (default `~/.cache/chiaki-video/assets3d`):
- **Poly Haven** (`polyhaven`): CC0 HDRIs, PBR materials, and 3D models — **no account, no API key**.
- **ambientCG** (`ambientcg`): CC0 PBR materials and HDRIs — **no account, no API key**.
- **Sketchfab** (`sketchfab`): downloadable CC models (`--license by,cc0`) — search needs no account; download uses the client's optional token in `<lib>/tokens.json` or `SKETCHFAB_TOKEN`.
- **BlenderKit** (`blenderkit`): free models, materials, and HDRIs — search needs no account; download uses optional `tokens.json` or `BLENDERKIT_API_KEY`.

```bash
python -X utf8 <sk>/scripts/assets3d.py search all "wooden desk" --kind model --license cc0,by
python -X utf8 <sk>/scripts/assets3d.py get polyhaven studio_small_09 --res 2k --project <project>
python -X utf8 <sk>/scripts/assets3d.py credits <project>
```

Inside any Blender Python script, load cached assets in one line with `scripts/blender/asset_lib.py`:
```python
import sys
sys.path.append("<sk>/scripts/blender")
import asset_lib as AL

AL.use_hdri(AL.find("polyhaven:studio_small_09"), strength=0.6, rotation=40, camera_sees=False)
floor.data.materials.append(AL.pbr_material(AL.find("ambientcg:WoodFloor051"), scale=2.0))
props = AL.import_model(AL.find("polyhaven:ArmChair_01"), height=0.9, location=(0.8, 1.2, 0))
```
- `import_model` automatically converts glTF `QUATERNION` rotations to `XYZ` Euler (otherwise `rotation_euler` edits silently fail), scales to real-world metres, and seats the mesh on `z = 0`.
- Always render **one full-res look-dev still** to verify light direction, mood, and grade before animating a batch. Keep a low base fill (`luma Y >= ~30`) so dark scenes never crush texture to solid black.
- Always run `assets3d.py credits <project>` at delivery so CC BY authors and Poly Haven appear on the end-credits card.

## 5c. Three families of real 3D
Real 3D means a Blender scene the camera genuinely moves through. Spread families across a film rather than repeating one trick:

| Family | What it is | Best fit |
|---|---|---|
| **1. Camera projection** | Illustration projected from its own camera onto proxies, then a true dolly (`scripts/blender/projection/`) | Intricate painted spaces where brushwork and bespoke detail matter (libraries, cathedrals, ornate corridors) |
| **2. Built set** | Real Blender set dressed from `assets3d.py` / `asset_lib.py` + custom geometry, mood-lit; optional 2D cutout placed as an unlit grounded card | Modular spaces (streets, rooms, studios, stages), long travel, look-arounds, props catching real light |
| **3. Optical mechanism** | 3D picture-making device whose look reacts to viewing angle or light (lenticular flip wall, halftone/LED matrix, prism, mechanical shutter) | Title/logo reveals, medium-driven transitions, beats where the image surface itself physically transforms |

### Grounding a 2D cutout inside a built Blender set (`asset_lib.py`)
- **Unlit tinted card**: `card = AL.emissive_card(png_path, width=1.18, location=(0, 0.22, z), glow=0.8, tint=(0.72, 0.6, 1.0))` keeps the illustration's own shading while blending brightness and room tint so it never reads as pasted on.
- **Contact shadow**: sink the card's bottom edge 2–4 cm below the resting surface, then call `sh = AL.contact_shadow(card, surface_z=DESK_Z)` to generate an alpha-shaped contact decal.
- **Match 3D props to 2D cel look**: `AL.anime_look(keep=[card], no_ink=[sh])` flattens harsh PBR gloss, applies anisotropic Kuwahara painterly filtering, and adds near-black Freestyle silhouette/border ink (skipping creases so dense meshes never turn into wireframes). Use `ink=False` during quick look-dev and `ink=True` for final frames.
- **Close hidden gaps**: if a half-body card sits behind a desk or counter, enclose the desk front/sides so the camera never peeks underneath to an empty cut.

## 5d. Live look-dev in open Blender (Blender MCP)
When the client has Blender open with **Blender MCP** enabled (official **Blender 5.1+ Lab MCP add-on** on `127.0.0.1:9876` via the bundled zero-dependency bridge `scripts/blender/mcp_bridge.py`, or community **`blender-mcp`** on Blender 4.2+ via `uvx blender-mcp`), the 3D engineer can inspect scenes, run live `bpy` tweaks, adjust camera/lights interactively, and render single look-dev stills in real time.

- **Golden split — live for look-dev, headless for batch rendering**:
  - Use **Blender MCP** for interactive **look-dev** (staging props, tweaking lights, letting the client nudge the camera and reading coordinates back into `shot.py`, checking Blender 5 API nodes).
  - **Never batch-render finals inside the open GUI**: GUI renders freeze Blender's window and block MCP calls. Always run final sequence renders headless through `scripts/run_queue.py blender -- blender -b --python shot.py -- ...`.
- **Dual-mode scripts**: write every custom `shot.py` with `LIVE = not bpy.app.background`:
  - When `LIVE` is `True`: build into a fresh scene (never wipe the client's unrelated file), accept parameters from a Python dict instead of `sys.argv`, leave GPU preferences untouched, and do not trigger a batch render.
  - Write every look-dev adjustment discovered live back into `shot.py` — the script stays the deterministic source of truth.
- **One window, one driver**: in parallel builds, only the `3D 工程师` touches live Blender MCP; all other crafts stay headless.
- **Limits to keep in mind**:
  - Viewport screenshots are low-resolution (~700 px) and EEVEE previews look flatter than Cycles without compositor nodes — judge framing and light placement live, then judge final colour and Kuwahara/Freestyle finish on a rendered Cycles still.
  - **Never run `taskkill /IM blender.exe`** (it kills the client's open Blender session); always cancel a runaway background render by its specific PID.
- **Graceful fallback**: if Blender MCP is not connected or Blender is closed, fall back seamlessly to headless scripts through `run_queue.py blender`.

## 5e. Three.js Stylized Graphic-3D (`lib/three_kit.js` + `fonts.py glyph3d`)

Bundled offline under MIT (`assets/template/lib/three/three.min.js` r160 classic script + `assets/template/lib/three_kit.js`), **Three.js Graphic-3D** brings real-time deterministic 3D directly into the 2D `<canvas>` timeline without breaking 2D graphic aesthetics or requiring photoreal PBR lighting. Even when Blender is installed, **dual-3D flagship films (`全能双 3D 旗舰`)** should pair **Three.js** for graphic/typographic/refractive 3D moments with **Blender** for cinematic environments and optical DOF.

### Setup (2 lines in `index.html`, zero build step, offline `file://` safe)
```html
<script src="lib/three/three.min.js"></script>
<script src="lib/three_kit.js"></script>
<!-- Optional: generated offline when using extruded 3D CJK/JP/Latin text -->
<script src="assets/fonts/glyph3d.js"></script>
```
- **Single shared WebGL context**: `T3.three.renderer()` creates ONE offscreen `WebGLRenderer` (`NoToneMapping`, `SRGBColorSpace`, `preserveDrawingBuffer: true`, deterministic 1920×1080) and blits each scene onto any 2D `<canvas>` via `T3.three.blit(ctx, scene, camera)` — never spin up multiple `THREE.WebGLRenderer` instances per act (Chrome caps WebGL contexts at ~8–16).
- **Anti-plastic graphic look**: never default to shiny Phong/Lambert grey spheres. Pick deliberate graphic looks built into `lib/three_kit.js`: **`'flat'`** (bold face vs side contrast like print/cel blocks), **`'toon'`** (stepped cel ramp + crisp inverted-hull black ink outline), **`'glass'`** (translucent chromatic crystal with specular highlight & fresnel rim), or **`'wire'`** (editorial architectural wireframe).

### True 3D Extruded CJK / JP / Latin Typography (`fonts.py glyph3d` + `T3.three.extrudeText`)
Standard Three.js `FontLoader` needs 15 MB typeface JSONs and fails on Chinese/Japanese fonts. Instead, compile **only the exact hero glyphs** offline from any bundled or Google TTF/OTF font into a tiny classic script (`assets/fonts/glyph3d.js`, typically 10–60 KB):
```bash
python -X utf8 <sk>/scripts/fonts.py glyph3d <project> "Smiley Sans" "星尘破晓WORLD" --alias hero3d
```
Then build and animate per-glyph 3D geometry deterministically in `render(t)`:
```js
const title3d = T3.three.extrudeText('星尘破晓', {
  font: 'hero3d',       // key from fonts.py glyph3d
  size: 1.0,
  depth: 0.28,
  bevel: 0.028,
  style: 'toon',        // 'flat' | 'toon' | 'glass' | 'wire'
  faceColor: '#FFF7EA',
  sideColor: '#D93848',
  outline: '#121318',   // crisp inverted-hull 2D ink edge
  outlineWidth: 0.025,
  letterSpacing: 0.14,
});
// In render(t): drive title3d.glyphs[i] stagger rotation/scale/z from T3.EZ.at(...) — 100% pure in t!
```

### Complete `T3.three.*` Toolkit (all registered in `references/motion-library.md`)
| Helper & Move ID | Best Fit | Key Pattern |
|---|---|---|
| `T3.three.extrudeText(text, opts)` (`type.3d-extrude`) | Hero 3D CJK/JP/Latin title slams, tumbling stone/cel blocks, glass wordmarks | Pair with `fonts.py glyph3d`; `title3d.draw(ctx, { rotY, each(piv, i){...} })` |
| `T3.three.textRing(text, opts)` (`type.3d-ring`) | 360° rotating lyric ribbon wrapping a 2D character cutout | **Z-sandwich**: `ring.drawBack(ctx, { rotY, tiltZ })` → draw 2D character RGBA → `ring.drawFront(ctx, { rotY, tiltZ })` so text passes cleanly behind shoulders and across chest! |
| `T3.three.textCorridor(items, opts)` (`type.3d-corridor`) | Lyric PV bridge / chorus fly-through of angled 3D typographic posters | Drive `corridor.draw(ctx, { camZ, camX, lookZ, roll })` on `T3.EZ` curves |
| `T3.three.prismOverlay(opts)` (`fx.3d-prism`) | Live chromatic glass prism refraction sweeping over 2D illustration/lyrics | Pass the live 2D `canvas` into `prism.draw(ctx, srcCanvas, { refract, chroma, each })` — refracts real underlying pixels with RGB dispersion & fresnel edge |
| `T3.three.louverTransition(opts)` (`trans.3d-louver`) | `z = 60` 3D flipping vertical/horizontal blinds cut across acts or shots | `louver.draw(ctx, fromCanvas, toCanvas, progress, { stagger, ease })` |
| `T3.three.field(opts)` (`cam.three-field`) | Stylized graphic-3D perspective grid, instanced monoliths & halo rings | `field.draw(ctx, { phase, scrollZ, pulse, camX, camY, camZ })` (transparent overlay over any 2D sky/bg) |
| `T3.three.relief(opts)` (`cam.three-relief`) | Zero-Blender GPU 2.5D depth-map mesh orbit/crane (uses `depth.py --soften`) | `relief.draw(ctx, { orbit, crane, push })` — exact sRGB illustration colour |
| `T3.three.stage(opts)` | Lightweight 3D stage placing 2D RGBA character/prop cutouts at real Z coordinates | `stage.addCard(img, { x, y, z, height })` + `stage.draw(ctx, { camX, camZ })` |

### Three.js Rendering & Determinism Rules
1. **100 % pure in `t`**: never drive rotation/position with `clock.getDelta()` or `+= 0.02`; always set `mesh.rotation.y = f(t)` directly so backward seeks and parallel `render_fast.mjs` workers stay frame-identical.
2. **CPU WebGL fallback safe**: all `lib/three_kit.js` shaders stay GLSL ES 1.0 / WebGL 1+2 compatible with moderate polygon budgets (`curveSegments: 6` on glyph extrusion, `64–128` mesh subdiv on `relief`), ensuring smooth headless rendering on both GPU ANGLE and SwiftShader (`CHIAKI_CPU=1`).
3. **Never stack conflicting 3D looks in one shot**: either let Three.js lead the shot's graphic 3D space, or overlay a restrained `prismOverlay` / `textRing` / `extrudeText` tuned to the exact colour tokens of the 2D art or Blender plate behind it.

## 6. Camera grammar & sequence playback (`lib/sequence.js` + `T3.relX`)
- **Design screen direction deliberately**: specify `--orbit ±`, `--crane ±`, push, pull, or truck per shot in the shot table so neighbouring shots vary naturally rather than drifting one way all film. Verify direction from `parallax.py`'s `background slides` readout.
- **Two playback rules (do not mix them up)**:
  1. **`depth_relief.py` sequences** (`web/assets/rel/<ID>/`) use Blender's SINE ease-in-out (`s = (1 - cos(pi * u)) / 2`). Play them with `frac: true` and **`T3.relX(s, count)`** (`time.relief` in `motion-library.md`) to invert SINE and apply any `T3.EZ` curve smoothly without end-frame parking:
     ```js
     const rel = T3.sequence(layer, { dir: 'assets/rel/shot01', count: 48, ext: 'png', blend: 'normal', frac: true });
     // render(t):
     const s = T3.EZ.at(f, f0, dur, 'p4out');
     rel.render(T3.relX(s, 48));
     ```
  2. **Camera projection & built-set sequences** (`web/assets/b3d/<ID>/`) already key the exact target curve per frame (`count = shot length`). Play them **frame-for-frame** (`rel.render(f - f0)`) with **no `T3.relX`** — applying `relX` would distort the baked curve.

## 7. Particles at depth (Canvas 2D camera projection)
Drive 2D foreground dust, sparks, or petals from the shot's camera coordinates so particles parallax naturally with Blender or multiplane layers:
```js
function proj(x, y, z, cam) {
  const d = z - cam.z;
  if (d <= 1) return null;
  const s = cam.f / d;
  return { x: 960 + (x - cam.x) * s, y: 540 + (y - cam.y) * s, s };
}
// Draw deterministic positions from T3.rand(i, ...) with radius r * p.s and depth-attenuated alpha.
```

## 8. 2D character motion inside a 3D shot
Attach split character layers (clean body + separated hair, veil, ribbons, eyes, props) onto the subject's depth plane:
- Animate hair and translucent veils with `her.wave` (`T3.her.wave` + two-pass `T3.her.warp2` via `lib/meshwarp.js`, `style-grammar.md` §6d) so soft alpha edges never seam.
- Animate ribbons, flags, and tails with `T3.meshwarp.sway` (zero displacement at root, growing with phase lag toward the free tip).
- A meshwarp canvas drops straight into `lib/multiplane.js` as `{ el: warp.canvas, z }`.
